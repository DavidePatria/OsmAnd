# Garmin platform feasibility: live OsmAnd junction display

Frozen platform research. The current implementation contract and verification requirements are in `../plan.md` and `../todo.md`; API availability here is not runtime validation.

Researched 2026-11-05. Target confirmed by user: **Forerunner 970 + Android, standalone watch app for motorcycling**. This report covers the Garmin side; OsmAnd data availability is assessed separately. No device experiment or SDK build was performed. Wrist and mounted layouts will share transport and navigation state.

## Assessment

**Feasible at the platform/API level.** An Android companion can send navigation state to a custom Connect IQ component, which draws a schematic junction. A standalone **device app** is the selected approach for motorcycling. A full-page **data field** remains an alternative for future integration into native Garmin activity recording. These are custom components to build, not a setting that makes OsmAnd appear inside Garmin's existing navigation screen. This architecture is an engineering inference from the supported extension points. [Garmin app types](https://developer.garmin.com/connect-iq/articles/connect-iq-basics/App_Types.html), [entry points](https://developer.garmin.com/connect-iq/articles/user-experience-guidelines/Entry_Points.html).

## Confirmed capabilities

- Garmin's current device table lists the **Forerunner 970 with a 454 × 454 round AMOLED display and Connect IQ API level 6.0**. This is comfortably suitable for a small vector diagram, although real wrist readability remains a design test. [Compatible devices](https://developer.garmin.com/connect-iq/compatible-devices/).
- **Foreground data fields can use `Toybox.Communications` from API 5.0.0.** Thus the 970 avoids the older-device workaround of receiving messages in a background service and forwarding state to the field. The module exposes phone-message callbacks and supports arrays/dictionaries/scalar values, suitable for compact geometry and navigation state. [Communications API](https://developer.garmin.com/connect-iq/api-docs/Toybox/Communications.html).
- Garmin supplies an **Android companion SDK**, available through Maven Central, and official Android/Monkey C communication samples. Its sample explicitly handles the Connect IQ service running inside **Garmin Connect Mobile**, including failure when Garmin Connect is absent or outdated. Keep Garmin Connect installed and paired as part of the proposed bridge. [SDK and samples](https://github.com/garmin/connectiq-android-sdk), [official device-discovery sample](https://github.com/garmin/connectiq-android-sdk/blob/main/Comm%20Android/app/src/main/java/com/garmin/android/apps/connectiq/sample/comm/DeviceListViewModel.kt).
- A custom data field can draw graphics in its assigned area. `DataField.compute()` receives activity information once per second, while drawing occurs in `onUpdate()` when displayed. **This is not a guarantee of one-second phone delivery latency.** [DataField API](https://developer.garmin.com/connect-iq/api-docs/Toybox/WatchUi/DataField.html).
- `Graphics.Dc` offers lines, arcs, polygons, text, colors, and pen width. Drawing a few road arms and a highlighted route does not require transferring raster screenshots or map tiles. Render only inside the provided update callback. [Graphics API](https://developer.garmin.com/connect-iq/api-docs/Toybox/Graphics/Dc.html).
- A data field may show a **full-page alert**, useful when another activity page is visible. Alerts are dismissible or expire, and **disabled by default** until enabled under activity settings → Alerts → Connect IQ. Data fields do not take ordinary direct user input; full-screen and smaller layouts need suitable presentations. [Data field UX](https://developer.garmin.com/connect-iq/articles/user-experience-guidelines/Data_Fields.html). The 970 is explicitly supported by the alert API. [DataFieldAlert](https://developer.garmin.com/connect-iq/api-docs/Toybox/WatchUi/DataFieldAlert.html).
- Garmin also offers a static `MapView`, including on the 970, with marker/polyline overlays. It is a potential separate experiment, but it displays Garmin's underlying map and is not an OsmAnd screen mirror or proof that arbitrary activity field layouts can host it. A phone-generated vector schematic is more directly controllable for this requirement. [MapView API](https://developer.garmin.com/connect-iq/api-docs/Toybox/WatchUi/MapView.html).

## Recommended protocol and validation (design recommendations)

Send normalized vector coordinates for the approaching junction, selected branch, approach bearing, distance, instruction, timestamp, sequence number, and route-generation ID. Send geometry on junction/route changes; send compact distance/progress updates between them. Keep navigation/rerouting on the phone. Highlight the chosen exit with a thick line and arrow; show alternatives faintly; use approach-up orientation. Include nearby successive junctions when one decision cannot be represented honestly by a single node.

The receiver should discard old generations/sequences and visibly mark stale/disconnected data. Prefetch the next few junctions for continuity, while treating phone rerouting as authoritative. Target a modest update rate first and measure actual delivery rather than assuming a streaming throughput guarantee.

Required real-device checks for the chosen standalone app: screen-off Android operation; Garmin Connect and bridge survival under the phone's battery policy; latency approaching turns; reconnect and reroute behavior; AMOLED brightness/gesture behavior; multi-hour battery impact; diagram readability while moving. Activity alerts and workout interaction apply only to a possible future data-field version.

## Limits and unresolved details

Background services are event-driven, may be terminated for higher-priority work, and are not a continuously running renderer. Temporal background events have a five-minute minimum interval, so periodic background polling is unsuitable for live navigation. Phone-message background events are distinct and exist from API 3.2. [Backgrounding guide](https://developer.garmin.com/connect-iq/articles/core-topics/Backgrounding.html), [Background API](https://developer.garmin.com/connect-iq/api-docs/Toybox/Background.html), [service lifecycle](https://developer.garmin.com/connect-iq/api-docs/Toybox/System/ServiceDelegate.html).

The exact 970 heap limits were **not verified**: the official device-reference URL returned the navigation shell without its model details through the research tool. Do not invent a memory number. A small vector scene should be modest, but confirm memory and message sizes in the downloaded device profile/compiler and real device before implementation commitments. [Official 970 device reference](https://developer.garmin.com/connect-iq/device-reference/fr970/).

API availability does not establish acceptable latency, unattended app activation, battery cost, or display-wake behavior during a long ride. Those remain prototype gates. The selected version is a standalone device app; native activity recording is not a requirement.
